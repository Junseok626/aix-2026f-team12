## 개요 / Overview

현재 AC는 최소 개수(정상 2개, 실패 1개)는 충족하지만 정상 동작의 판정 기준과 실패 후 처리에 빈틈이 있음. AC-1~3을 구체화하고, 강좌는 존재하나 일부 정보 누락·조회 실패 상황을 보완하는 것이 우선.

> 이 문서는 **명세 검토 결과**이며, 구현·테스트 결과가 아님. "문서 근거"는 기존 요구에서 도출한 사항, "권장·가정"은 팀 결정이 필요한 추가 제안.

## 검토 기준 / Review criteria

- 조건·주체·동작·결과의 명확성, 실패 경로 병기, 숫자·목록을 통한 판정 가능성 (강의자료 8~15쪽)
- AI가 제시한 후보의 채택 여부는 사람이 최종 판단

## 1. 기존 AC와 중복 여부 / Overlap with existing ACs

| AC | 현황 | 보완 방향 |
|---|---|---|
| AC-1 과목 정보 표시 | 커리큘럼·강의평·수강시간 표시 포함 | "한 화면" 조건, 선택 과목·표시 데이터 일치 여부 보완 (신규 AC 아님) |
| AC-2 시간표 및 중복 점검 | 요일·시간 표시, 중복 점검 포함 | 충돌 사례만 확인 → 충돌 없는 추가 / 충돌 후 처리 분리 |
| AC-3 학년별 커리큘럼 | 문장은 "탭 열기", 판정은 "학과 입력"으로 조건 불일치 | 학과 선택 조건 통일 + 학년별 분류 검사 추가 |
| AC-4 DB에 없는 강좌 | 기존 예외 경로 | "DB에 없음"="미개설" 여부 확인, 안내 문구 정확성 검사 |

## 2. 정상 패스 보완 후보 (기존 AC 수정안) / Happy-path additions

### N1 · AC-1 보완 — 한 화면과 데이터 일치
- **WHEN** 학생이 세 정보가 등록된 강좌를 선택하면 **THE** 시스템은 **SHALL** 선택 강좌에 연결된 커리큘럼·강의평·수강시간을 한 화면에 표시한다.
- 판정: 서로 다른 데이터를 가진 강좌 A·B 준비 → 각각 선택해 세 영역이 기준 데이터와 일치하고 화면 이동 없이 확인 가능한지 검사
- 결정 필요: 화면 내 스크롤 허용 여부

### N2 · AC-2 정상 분기 — 충돌 없는 추가
- **WHEN** 학생이 기존 시간표와 겹치지 않는 강좌 추가를 요청하면 **THE** 시스템은 **SHALL** 해당 강좌를 시간표에 추가하고 모든 수업의 요일·시작·종료 시각을 표시한다.
- 판정: 빈 시간표에 A 추가 후 겹치지 않는 B 추가 → 모든 시간이 기준 데이터와 일치하고 충돌 표시 없는지 확인
- 권장: "넣게 되면"을 추가 요청과 완료 결과로 명확화

### N3 · AC-3 보완 — 학과·학년별 커리큘럼
- **WHEN** 학생이 커리큘럼 데이터가 등록된 학과를 선택하고 탭을 열면 **THE** 시스템은 **SHALL** 해당 학과 커리큘럼을 학년별로 구분해 표시한다.
- 판정: 학과 A·B의 학년별 기준 데이터 준비 → 학과 일치·학년 구분·과목 목록 일치 확인
- 권장: "학과 입력"을 학과 선택으로 표현 통일

> **핵심**: 화면에 정보가 "나오는지"만 확인하면 다른 과목 정보나 일부 누락도 통과할 수 있음 → 기준 데이터와 실제 표시 결과를 비교해야 함

## 3. 실패·예외 패스 후보 / Failure & exception paths

### F1 · AC-2 분리 — 시간 충돌
- **IF** 추가 요청 강좌의 수업 시간이 기존 강좌와 겹치면 **THEN THE** 시스템은 **SHALL** 충돌 강좌명과 겹치는 시간 구간을 표시하고 기존 시간표를 변경하지 않는다.
- 판정: 월 09:00~10:00 A 존재 시 09:30~10:30 B 추가 → 충돌 강좌·겹침 구간(월 09:30~10:00) 표시, 시간표 불변 확인
- 권장 정책: 충돌 시 추가 차단 (경고 후 허용 정책 채택 시 결과 변경 필요)

### F2 · 신규 — 강의평 없음
- **IF** 강좌는 존재하나 강의평이 0건이면 **THEN THE** 시스템은 **SHALL** 강의평 영역에 "등록된 강의평이 없습니다"를 표시하고 커리큘럼·수강시간은 정상 표시한다.
- 판정: 강의평만 0건인 데이터 선택 → 안내 문구와 나머지 두 영역 확인
- AC-4(강좌 자체 없음)와 구분됨

### F3 · 신규 — 커리큘럼 없음
- **IF** 선택 학과의 커리큘럼 데이터가 없으면 **THEN THE** 시스템은 **SHALL** "등록된 커리큘럼이 없습니다"를 표시하고 이전 학과 데이터를 남기지 않는다.
- 판정: 학과 A 조회 후 데이터 없는 학과 B로 전환 → 안내 표시 및 A 데이터 잔존 여부 확인

## 4. 조건부 후보 (팀 결정 필요) / Conditional candidates

### F4 · 신규 — 조회 실패
- **IF** 강좌 정보 조회가 서버 오류로 종료되면 **THEN THE** 시스템은 **SHALL** "강좌 정보를 불러오지 못했습니다"와 재시도 버튼을 표시한다.
- 전제: 서버를 통한 조회 구조. AC-4(DB에 강좌 없음)와 조회 실패는 구분. 재시도 버튼 클릭 후 동작은 별도 정의 필요

### F5 · 신규 — 수업 시간 미등록
- **IF** 추가하려는 강좌의 요일·시작·종료 시각 중 하나 이상이 누락되면 **THEN THE** 시스템은 **SHALL** "수업 시간 정보가 없어 추가할 수 없습니다"를 표시하고 시간표를 변경하지 않는다.
- 가정: 시간 미등록 강좌가 존재할 수 있으며 추가를 차단한다는 정책

## 5. 채택 전 결정 사항 / Decisions before adoption

1. **충돌 기준**: 같은 요일에 `A시작 < B종료` 이고 `B시작 < A종료`인 경우 (권장). 이 기준에서는 09:00~10:00과 10:00~11:00은 충돌 아님. 부분 겹침·포함·완전 일치·경계 접촉·다른 요일 테스트 필요
2. **AC-4 문구**: DB가 전체 개설 강좌를 보장하지 않는다면 "해당 강좌를 찾을 수 없습니다"가 더 정확할 수 있음
3. **시간 제한**: 강의자료의 3초·5초는 예시일 뿐 팀 요구 아님. 타임아웃 AC 채택 시 측정 시작점·제한 시간 합의 필요
4. **범위 제외**: 삭제·저장 유지·로그인·실제 수강신청·정원 초과 처리는 이번 검토에서 확정 누락으로 분류하지 않음

## 권장 적용 순서 / Recommended order

N1~N3 보완 → F1 충돌 정책 명확화 → F2·F3 빈 데이터 처리 → 구조·데이터 정책에 따라 F4·F5 채택

> F2~F5의 발생 가능성과 대응 정책은 아직 팀 문서에서 확정되지 않은 제안임
